# Security and data handling

This repository is a sanitized portfolio source extract, not a production deployment or security certification.

- Keep real credentials, API keys, tokens, datasets, customer documents, session exports and generated reports outside Git.
- Copy example configuration locally and replace every placeholder before any deployment. Keep local .env files ignored.
- Configure TLS, origin allowlists, trusted proxy behavior and access controls for your environment. Example local bindings and Compose services are not a public-service recommendation.
- Supply only data and external engines you have permission to use. Review map-provider terms before enabling map layers.
- Review backup/restore and administrator commands before use; restoration can overwrite data.

Do not put credentials or customer information in public issues. Agree a private reporting channel with the maintainer for sensitive security findings. An edited historical engineering-review excerpt is included for portfolio context; it omits deployment addresses, credentials, customer/result data and environment-specific traces. It does not establish present vulnerability status. The four portfolio screenshots and all three GIF frames are English-annotated original captures, flattened or re-encoded with opaque data-protection masks. Major labels and explanations are translated for portfolio readability, not presented as native-English runtime screenshots or an English-localized product. Original layout, branding and workflow are retained; the application interface and source remain Korean. English SQL field labels and readable excerpts are reading annotations, not newly executed queries or a migrated schema. No synthetic assessment values or replacement numerical results are supplied. GIF playback is not execution latency. Do not upload unredacted replacements or raw reports.
